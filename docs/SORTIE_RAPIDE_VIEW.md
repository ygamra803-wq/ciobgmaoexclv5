# 📖 التوثيق الفني والوظيفي الشامل: شاشة Sortie & Entrée Rapide

هذا الملف يمثل المرجع الهندسي الشامل والكامل لشاشة **Sortie & Entrée Rapide** (المكون البرمجي: `src/components/SortieRapideView.jsx`)، ويشمل الفلسفة الوظيفية، أدوار كافة الأعمدة، الفرق بين المنفذين والطلاب، تدفقات الحركة الخمسة، المنطق البرمجي، والتطابق الدقيق مع ورقة إكسيل `Mouvements`.

---

## 🧭 1. الفلسفة والهدف الوظيفي (Core Philosophy)

شاشة **Sortie & Entrée Rapide** هي الشريان التنفيذي لنظام الصيانة والمخازن (**GMAO / Gestion de Stock**). تم تصميمها لتحقيق الأهداف التالية:

1. **السرعة والسهولة في بيئة الورشة والمستودع:**
   - واجهة إدخال ذكية وفورية تدعم الفحص بالباركود والبحث التلقائي عن قطع الغيار بمجرد كتابة الرمز أو المسح الضوئي.
2. **الشفافية والتتبع الكامل (100% Traceability):**
   - تسجيل كل حركة مخزون مع ربطها بالسياق الثلاثي: **من الفني؟** (`Intervenant`)، **ما هي الآلة/المنطقة؟** (`Machine/Zone`)، و**ما طبيعة التدخل؟** (`Action ID: Corrective / Préventive / Usage`).
3. **التطابق الصارم مع نموذج إكسيل (Excel Twin Model):**
   - كل حركة تُخزن في قاعدة البيانات المحلية بما يطابق تماماً أعمدة ورقة `Mouvements` من العمود `(A)` حتى العمود `(L)`.
4. **التأهيل التفاعلي والمرن للحركات (Data Qualification):**
   - إمكانية تأهيل وتصحيح الحركات السابقة أو غير المصنفة (`INCONNU` / `MACHINE`) بنقرة واحدة مباشرة من داخل الجدول دون الحاجة إلى حذفها أو إعادة إدخالها.

## 📊 2. هيكل جدول الحركات في إكسيل (Excel Columns Blueprint A → L)

يتطابق جدول الحركات في الواجهة بدقة مع جدول `Mouvements` في ملف إكسيل:

| العمود في إكسيل | اسم الحقل في الواجهة | اسم الخاصية البرمجية (`JSON Key`) | الوصف والنوع |
| :---: | :---: | :---: | :--- |
| **(A)** | **N°** | `id` / `index` | الرقم التسلسلي التلقائي للسطر (Index). |
| **(B)** | **Bon / Date** | `code_bon` + `date` | رقم وصل الصرف/الدخول (مثل `Bon-001`) وتاريخ تسجيل الحركة (`YYYY-MM-DD`). |
| **(C)** | **N° OT / CMD** | `num_commande` | رقم أمر العمل أو طلب الشراء المرتبط بالعملية (`OT-xxxx` أو `CMD-xxxx`). |
| **(D)** | **Type (5 Flux)** | `type` | نوع التدفق المخزني (انظر قسم التدفقات الخمسة أدناه). |
| **(E)** | **Action ID** | `action_id` | طبيعة الإجراء أو نوع الصيانة (`CORRECTIVE`, `PREVENTIVE`, `AMELIORATIVE`, `USAGE`, `REAPPRO`, `RETOUR`, `REPARATION_EXTERNE`, `SOUS_TRAITANCE`). |
| **(F)** | **Réf & Article** | `ref` (+ `designation`) | المرجع الفريد للمقال (`Ref`) واسم القطعة المستخرجة من جدول المخزون. |
| **(G)** | **Qté** | `quantite` | الكمية المدخلة (+) أو المصروفة (-) بالأرقام الصحيحة/العشرية. |
| **(H)** | **Machine** | `id_machine_registered` | رمز الآلة التي تم تركيب القطعة عليها (مثل `CNC-01`). يُعطل عند الإدخال أو الاستخدام العام. |
| **(I)** | **Zone / Empl.** | `id_zone` / `emplacement_reception` | المنطقة الجغرافية في المصنع أو موقع التخزين في المستودع (مثل `R1-B04`). |
| **(J)** | **Intervenant** | `technicien` (`id_technician`) | الفني أو الميكانيكي المنفّذ للعملية والمستلم للقطعة. |
| **(K)** | **Demandeur** | `operation` (`id_operation`) | المشرف أو المشغل أو رئيس الفريق الطالب للصرف أو المستفيد من القطعة. |
| **(L)** | **Motif / Commentaire** | `commentaire` | ملاحظات إضافية، سبب العطل، أو توصيف خاص للعملية. |

## 👥 3. تفصيل دقيق: الفرق بين المنفّذ (Intervenant) والطالب (Demandeur)

من أكثر المفاهيم أهمية في نظام الصيانة والمخازن هو الفصل بين **المسؤولية التقنية الميدانية** و**المسؤولية الإدارية/التشغيلية**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           حركة صرف مخزني (Sortie)                           │
└─────────────────────────────────────────────────────────────────────────────┘
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼                                                 ▼
┌─────────────────────────────────┐               ┌─────────────────────────────────┐
│   المنفّذ (Intervenant / Tech)   │               │   الطالب (Demandeur / Chef/Op)  │
│          العمود [J]             │               │          العمود [K]             │
├─────────────────────────────────┤               ├─────────────────────────────────┤
│ • الصفة: فني صيانة / تقني       │               │ • الصفة: رئيس فريق / مشغل إنتاج │
│ • السؤال: من نفّذ العمل وركّب؟  │               │ • السؤال: من طلب / وافق / استهلك?│
│ • الجدول المرجعي: Techniciens   │               │ • الجدول المرجعي: Operations    │
│ • مثال: "حمزة - TECH-01"        │               │ • مثال: "CHEF-01" أو "OP-02"    │
└─────────────────────────────────┘               └─────────────────────────────────┘
```

### أ. المنفّذ / المتدخل (`Intervenant / Technicien`) — العمود `[J]`
- **الدور:** هو الشخص الفني الذي قام بفك وتركيب القطعة، استلمها من المستودع، ونفّذ التدخل التقني.
- **الفائدة التحليلية:**
  - حساب ساعات العمل وتكلفة تدخل كل فني.
  - معرفة أداء الفنيين ومعدل استهلاكهم لقطع الغيار.

### ب. الطالب / صاحب الطلب (`Demandeur / Opérateur / Chef`) — العمود `[K]`
- **الدور:** هو رئيس الورشة، المشرف، أو مشغل الماكينة الذي اكتشف العطل أو قدّم طلب الصيانة أو استلم المواد للاستهلاك العام (`USAGE`).
- **الفائدة التحليلية:**
  - تتبع الأقسام أو خطوط الإنتاج أو الفرق التي تستهلك ميزانية الصيانة وقطع الغيار.
  - الرقابة على أذونات الصرف والطلبات المعتمدة.

## 🔄 4. التدفقات الخمسة لحركات المخزون (The 5 Movement Flows)

يدعم النظام خمسة أنواع رئيسية للحركات المخزنية:

```
1. 🔴 Sortie Interne (Stock → Machine):
   صرف قطع غيار من المستودع وتركيبها على آلة محددة داخل المصنع (صيانة تصحيحية، وقائية، أو تحسينية).
   
2. 🔵 Entrée Interne (Machine → Stock / Retour):
   إرجاع قطع غيار غير مستخدمة، أو قطع صالحة تم فكها وإعادتها إلى رصيد المستودع.
   
3. 🟣 Sortie Externe (Stock → Réparation Extérieure):
   إخراج قطع أو معدات لإرسالها للإصلاح لدى ورش ومقاولين خارجيين (Sous-traitance).
   
4. 🟢 Entrée Externe (Achat / Réapprovisionnement):
   دخول قطع جديدة تم شراؤها من الموردين وتخزينها في رفوف وأماكن المستودع.
   
5. 🟡 COMMANDE (En attente de livraison):
   تسجيل طلبيات الشراء قيد الانتظار لمتابعة تواريخ الوصول والكميات المتوقعة.
```

## 🛠️ 5. منطق تأهيل وتصحيح الحركات السابقة (Action Qualification)

عند استيراد ملفات إكسيل قديمة أو بيانات سابقة، قد تحتوي بعض الحركات على قيم غير معيارية مثل `action_id = "machine"` أو `action_id = "INCONNU"`.

### آلية المعالجة الذكية في الواجهة:
1. **التعرف التلقائي:** يتم تمييز الحركات غير المصنفة بشارة كهرمانية تفاعلية بارزة `INCONNU (À qualifier)`.
2. **نافذة التأهيل السريع (`Quick Action Popover`):** بالنقر المباشر على الشارة داخل الجدول، تظهر قائمة فورية لاختيار التصنيف الصحيح (`CORRECTIVE`, `PREVENTIVE`, `AMELIORATIVE`, `USAGE`, `REAPPRO`, إلخ) مع حفظ التعديل فوراً.
3. **فلتر مخصص:** تم توفير خيار فلترة خاص في القائمة المنسدلة: `INCONNU (À qualifier / Ancien "MACHINE")` لعزل كافة الحركات غير المؤهلة ومعالجتها دفعة واحدة.

## 💻 6. المعمارية التقنية والمكونات البرمجية (Code Architecture)

المكون `SortieRapideView.jsx` مبني وفق أفضل ممارسات React والأداء العالي:

### أ. إدارة الحالة والذاكرة (State Management):
- `filteredMouvements` عبر `useMemo`: لضمان تصفية آلاف الحركات في أجزاء من الثانية وفق معايير متعددة (البحث، الفترات الزمنية، نوع التدفق، ونوع الإجراء).
- `displayedMouvements` مع التصفح والتقطيع (`Pagination / PageSize`): لمنع تجمّد المتصفح أثناء عرض كميات ضخمة من البيانات.

### ب. تكامل الأيقونات والتصميم:
- الاعتماد بنسبة **100% على أيقونات SVG دون اتصال** من مكتبة `lucide-react`.
- منع استخدام الرموز التعبيرية (Emojis) كعناصر تحكم رئيسية وفقاً لمعايير وثيقة `AGENTS.md`.

### ج. التنسيق والطباعة والتصدير:
- دعم التصدير الفوري إلى ملفات Excel متوافقة بالكامل مع الصيغ الحسابية.
- دعم الطباعة المباشرة لوصولات الصرف والتسليم مع الباركود والرأسية الرسمية.
